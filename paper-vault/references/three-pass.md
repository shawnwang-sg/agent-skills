# 三遍法内容规范（three-pass）

依据 S. Keshav《How to Read a Paper》。三个模式对应三遍阅读，**每一遍有固定的目的和产出**。
原文比例只是其中一项检查，不是三遍法本身。

下文「kind」是 section 的 `kind` 字段，`validate.py` 按它找每个部分。所有门槛见 `quality-gates.md`。

## 共同规则

- 原文块：`type` 为 `p` 或 `quote`，带 `origin: "paper"` 和 `source_page`（PDF 页码，从 1 开始）。
  - `en` 必须是原文，可以截取，不能改写。
  - 规范化后，必须能在那一页逐字找到。
  - 同一模式里不能重复。
- 讲解块带 `origin: "editorial"`，原文比例只统计原文块。
- 每个内容块中英成对（见 `schema.md`）。
- 讲解里的数字和结论要能指回原文段落或图表；写不出出处的，不写。

## 第一遍：鸟瞰（skim）

**目的**：用 5–10 分钟决定值不值得读下去。对应 Keshav 第一遍：读标题、摘要、引言、各章标题、结论，扫一眼参考文献，回答 5C。

| kind | 内容 |
|---|---|
| `conclusion` | 一句话结论：这篇论文解决了什么问题，靠什么，结果如何 |
| `five_c` | 一个 `terms` 块，5 项：Category 类别、Context 背景（和哪些工作有关）、Correctness 假设是否成立、Contributions 贡献、Clarity 写得好不好。每项都要落到这篇论文，不写套话 |
| `concepts` | **技术分析与基础概念**（单独一页，放在 5C 之后）。先讲读懂这篇论文必须知道的基础概念，每个一个 `h3`：是什么、为什么这篇论文需要它、举一个小例子。再做技术分析：这篇论文的方案在整体上怎么运作、关键设计取舍、和常见做法比强在哪、代价是什么。合计 ≥ 8 个小标题，讲解 ≥ 800 个英文词（中英成对，属于讲解，不算原文比例） |
| `excerpts` | 原文摘录：摘要、引言里的问题和贡献句、各章标题（`list`）、结论原句 |
| `verdict` | 值不值得深读、为什么、适合谁读、可以跳过哪些章节 |
| `questions` | 读完这一遍能回答的 3 个问题（`list`），带简短答案 |

原文比例 15–25%。

## 第二遍：理解（grasp）

**目的**：抓住主线和证据，先不纠缠证明细节。对应 Keshav 第二遍：仔细看图表，标出没读懂的地方和该补读的参考文献，能向别人讲清主旨和证据。

| kind | 内容 |
|---|---|
| （按论文章节，kind 可写 `chapter`） | 每个正文章节一节，节标题对应原文章节。每节：关键原文 + 逐段译文 + 一段讲解「这节在说什么、为什么重要」 |
| 图表 | 论文**每一张编号图和表**都要出现：`figure` 用原页裁图（`src`），`caption_en/zh` 写解读：这张图证明了什么、该看哪里、有没有坑（≥ 15 个英文词） |
| 术语 | `terms` 块，合计 ≥ 8 个术语，每个带一句白话解释 |
| `evidence` | 证据链 `list`，≥ 3 条：主张 → 支撑它的图表或实验 → 结论是否站得住 |
| `open_questions` | 没读懂的地方、需要补读的参考文献（`list`） |

至少 6 节，原文比例 30–45%。

## 第三遍：吃透（master）

**目的**：在脑子里把这篇论文重做一遍。对应 Keshav 第三遍：虚拟复现，质疑每个假设，找出隐藏的前提、缺的引用和实验问题，想到能接着做的工作。

| kind | 内容 |
|---|---|
| `reproduction` | 关键原文精读：核心机制、算法、实验逐段原文 + 译文，`h3` 按原文章节分节。正文 ≥ 8000 词的论文至少 40 段原文；更短的论文按「词数 ÷ 200」折算，最少 10 段 |
| `derivations` | 机制推演，≥ 12 项，每项一个 `h3`。用小例子手算一遍关键机制、公式或算法，写清输入、步骤、结果（可用 `math` / `code`）。能跑的放进这篇论文的审核脚本里跑一遍 |
| `qa` | 问答 ≥ 24 组。每组 `qa` 块带 `cat`，五类各 ≥ 3 组：`reproduce` 复现、`assumption` 质疑假设、`failure` 隐藏前提或失败场景、`evidence` 实验是否可信、`compare` 和其他论文对比。答案至少 3 句（英文 ≥ 40 词），至少 1/3 的答案引用具体图表、章节或数字 |
| `critique` | 4 个 `h3`：强项、弱项、隐藏假设、缺的引用或实验；每个下面一个 `list`，各 ≥ 2 条 |
| `future` | 我会怎么改进或接着做（`list`，≥ 2 条） |
| `structure` | 全文结构骨架（`list`） |

原文比例 40–60%。

## 怎么做（顺序不能乱）

1. 先下载原始 PDF，生成 `source.pdf`、`source.txt`、`source.json`（sha256、页数、从 PDF 提取的全文词数）。见 `fetch.md`。
2. 把每张编号图和表裁成原页图片，存进 `assets/`。在 `assets/provenance.json` 里每张记：`file`、`label`（如 "Figure 3"）、`source_page`、`rect`、`sha256`。
3. 依次写第一遍、第二遍、第三遍，逐段核对原文。
4. 运行 `python validate.py --vault <vault> <slug>`，按报告补齐，直到通过。
5. 运行 `validate.py --write`，由校验结果写入 `reading_status`；再 build，单独提交这一篇。
6. **新批次先做 1 篇样稿给用户看**，认可后再一篇一篇往下做。禁止多篇一起生成、一起提交。
