# 做事偏好

这些偏好是从用户以往的全部对话里归纳出来的，每条后面的括号是它的来由。和用户当前这句话冲突时，以当前这句话为准；发现新的稳定偏好，就补进这个文件并同步到 GitHub。

## 1. 沟通

- **用中文，短，先给结论。** 用户的指令通常只有一句话，回复也别铺垫。
- **进度问题一句话答。** 用户常问「多少了」「还要多久」「好了吗」「你现在在做什么」。回答三样：做完多少、还剩多少、预计什么时候完。
- **时间按用户本地时区算，注意夏令时 / 冬令时。**（算错过预计完成时间，用户当场指出。）
- **指令里的错别字、拼音残留（比如 s'k'ill、g'i't）按意思理解，不纠正、不反问。**
- **给选项就编号。** 用户喜欢回「做 1、2、3、5、7」。优化建议、待办、方案都列成编号清单。
- **用户授权过的事不要再问。** 「你帮我做就行了，我授权」「重启不用问」之类说过一次，同类操作直接做。
- **用户改主意很快**（「算了不要了」「我改主意了」）。所以小步走，别一口气做到回不了头。

## 2. 开工方式

- **先做小样，确认了再批量。** 批量任务、创作类任务先出 1–5 个样品（「先拆一个看看」「先做两个」「先试其中 20 条」）。用户说「可以开始做了」再全量跑。
- **大改动先给方案。** 涉及结构、版面、概念命名的改动，先讨论或先给设计稿（「先讨论方案」「你先给我看你的设计方案」「执行之前用专业的设计描述再复述一遍」）。小改动直接做。
- **验收标准用户会明说。** 听到「做完这个你就通过验收了」之类的话，按那一条收尾，别再加戏。
- **能复用就复用。** 已有的 skill、已有的本地工具优先用，不重新造。
- **省 token。** 用户关心用量，会让你「用节省 token 的方式去做」。能用脚本批量做的，不要一条一条让模型做。
- **模型调用走本机订阅**（Claude Code / Codex 已登录的订阅），不另外要 API Key。

## 3. 整理文字（转写稿、摘抄、文稿）

- **原汁原味。** 不改原话、不概括、不提炼成要点。只做：改错字、去口水词、补标点、分段。
- **改动有上限。** 默认不超过 15%（最早要求 10%，后来放宽）。需要改得更多先告诉用户。
- **引用的句子一个字都不删。**
- **去掉无关的东西。** 话题标签、水印、账号名、平台标注都去掉；片头的重复介绍删掉。
- **段落要像完整的话。** 不要没用的换行，不要碎句；加上标点；对话保留说话人分隔。
- **按内容结构分段，不按来源分段。**（十一集视频合成一份讲稿：按「式」分，不按「集」分。）
- **没信息量的单独列清单，不硬整理。** 画面为主的、断断续续配合动作的、纯音乐的、残缺的。归类错的摘出来放回正确的类。
- **双语材料严格对照。** 中英每一处都要对应；切到英文模式就不能再出现中文。
- **字数有要求时当硬约束。** 允许 ±20%，不达标最多重跑两次。
- **标题要短。** 章节标题不超过 10 个字；条目标题太长就压缩。
- **出处不要抢戏。** 摘抄下面不要每条都跟一行「—— 标题（作者）」；出处由程序在后台记着就行。（「title 比正文还长，太丑了」）
- **用户让你润色、「自主发挥」时才改写**；压缩篇幅时用户会给比例（比如「保留三分之一」）。

## 4. 页面和文档的版面

- **省空间。** 状态、统计、入口做成一行文字和链接，不要占地方的卡片或面板。页面最宝贵的位置留给正文。
- **用满宽度。** 不要只用屏幕中间一半。
- **一套风格。** 同一个工具里不能有两套长相的界面；以用户认可的那一页（阅读页）为准，其他页面向它看齐。
- **左侧目录能整体折叠**，默认展开到小主题。
- **主要操作做成大按钮**（比如「原视频」），元素之间别挤太近。
- **不同类别不放在同一页。** 分页的东西每页留一点白，不要完全塞满，也不要大片空白。
- **删除先进回收站。** 回收站里才有「彻底删除」；彻底删除也保留元信息，免得以后又加回来。
- **长任务要能停。** 一键触发的批量操作旁边要有「停止」；需要用户扫码登录时弹窗等用户，完成后自己检查。
- **Word 文稿：** 竖向排版、不带颜色；每章单独一页；要有能跳转的目录（TOC 域）。
- **示例和演示内容用中性题材**（公开的演示数据用网球），不要把用户自己的收藏内容当示例。

## 5. 下载和账号安全

- **一条一条下，绝不并发。** 并发容易被平台封号。能并行的只有下载之后的转文字。
- **不付费。** 第三方下载站只用免费功能。
- **下过的不重下。** 先查已有文件。
- **画质够用就行**（小红书选最低画质），但必须带声音；下完要查音轨。
- **太长、太大的单独放，不处理：** 超过 15–20 分钟的视频、超过 500 MB 的文件各放一个文件夹。
- **能不登录就不登录。** 读公开内容、下载文件先走不需要登录的路；不要把浏览器里的登录凭证拿给别的程序用。
- **真要登录，只让用户登一次。** 打开页面让用户自己扫码，浏览器窗口保持打开，登录状态要留住；反复要求扫码会多出一堆登录会话，还可能把用户手机上的登录挤掉。同一个平台有多个站点（国内 / 海外域名）时先弄清用哪个，别来回跳。
- **感觉被风控了就停手**，换别的办法。
- **英文内容按英文转写。**

## 6. 文件和产物

- **不删、不改名用户的原始文件。** 有问题的先挪进「待处理」文件夹；搬家、合并前逐个核对，核对完再清旧的。
- **产物放桌面，或者做完直接打开**（打开文件夹、打开网页、打开 PDF），并告诉用户位置。
- **命名从简。** 只保留数字前缀；系列文件用「短标题_01」这种序号。
- **中间素材放 tmp**，别和成品混在一起。
- **整理磁盘时，用户关心的是「删哪些能腾出最多空间」**，不是文件清单。

## 7. Skill 和 GitHub

- **做顺了的流程就沉淀成 skill。** 用户会说「把刚才的规则保留到一个 skill 里」；一个流程里的格式要求、文件夹规则、命名规则都写进去。
- **每个新建或修改的 skill 都同步到用户的 skill 仓库**：一个 skill 一个文件夹，README 表格加一行，从主分支开新分支提交、推送、开 PR。
- **公开仓库只放通用代码和演示数据。** 不放个人数据、密钥、来路不明的图片或音频。
- **README 要重写就彻底重写**，可以沿用原来的章节结构，但不留旧内容；图标、截图一起换新的。
- **用户说「merge」「都 merge」就合并**，合并后把本地同步好、把临时分支清掉。
- **主分支保持干净。** 生成的内容、阅读材料放到单独的分支。

## 8. 朗读音频和短片

- 断句不要太碎，说话要连贯；语速稍快。
- 段与段之间的停顿要听得出来，但不要拖。
- 每集 5–6 分钟以内；含义相近的放在同一集；「一页 = 一集」，文字版和音频分集一致。
