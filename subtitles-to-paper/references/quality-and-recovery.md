# 验收、交付与恢复

## 内容检查

1. 确认排版输入与最新确认正文逐段一致，并记录输入 SHA-256。不要只对比同一个旧文件派生出的两个结果。
2. 对原字幕检查所有 cue 的去向：进入哪个发言段、标为无语音、或因用户指定范围排除。检查异常空隙、重复、首尾以及多段接缝，不把字幕长度当作音轨覆盖证明。
3. 英中段落 ID 序列一致、说话人一致、信息范围一致；未确认内容保留对应方括号。输入未提供准确时轴时不要求或伪造最终 SRT。
4. 编者介绍、导读和篇末引用不计入访谈发言数量，完整引用位于全部正文之后。引用编号与来源表对应。

## PDF 检查

- 验证编译退出状态、PDF 可打开、页数和 US Letter 页面尺寸；检查缺字、未解析引用和实质性溢出。
- 从 PDF 抽取正文逐段核对文字和对话 ID。双栏要先左后右；首页全宽标题单独处理，排除页眉页脚，再拼接跨栏段落。不能用默认横向文本顺序误判正文错序。
- CJK 标点位置可能受排版压缩影响，比较时只对已确认的相邻标点差异做有限归一，不能忽略普通文字、数字或否定词差异。
- 渲染首、次、中、末页；不超过四页时看全部页面。完整导读另查其起止、正文起始和引用页。检查栏宽、孤立说话人、空白页、长 URL、页码及方括号。
- 正文、标题、链接为黑色；确认使用的字体实际可见且已嵌入或按输出环境正确处理。轻微标点悬挂结合图像判断，不能一律忽略所有 overfull。
- 检查对话 ID 全部出现且顺序正确，来源链接能对应原始目标。文字检查和页面渲染都通过才能交付。

保存简短 QA 记录：源哈希、原文语言、所出语言、段落/ID 数量、PDF 页数、文本检查结果、抽查页码、编译器与字体、剩余疑点和实际回听状态。辅助脚本的 manifest 仅是生成记录，不代表 QA 已通过。

## 交付

每篇默认交付相应语言的论文 PDF 与 UTF-8 TXT；用户明确只要 PDF 时，其余文件内部保留，不强加额外交付项。保存原字幕、校订中间稿、JSON 映射、TeX、manifest 和 QA，便于修改重排。逐条校准过的 SRT 可以作为终稿交付；阅读稿完成但时间轴未核验时，不能把来源 SRT 称为最终字幕。

放入用户指定文件夹；未指定时选择工作区内清晰的输出位置并报告完整路径，不固定用户名或猜测下载目录。交付副本与构建成果核对哈希，不覆盖既有版本。

Git 归档仅在当前任务需要时进行：保留字幕、正文、映射、TeX、技能、QA 和 PDF；忽略媒体、模型、缓存、渲染图片、安装包和凭据。既有 PDF 不因体积大被静默删除，不自动配置远程、提交或推送。

## 故障与继续

| 现象 | 处理 |
|---|---|
| 输出存在但命令非零退出 | 核对内容、完整性及实际错误；存在不等于成功，也不盲目重做已有成功步骤 |
| PDF 抽取错序 | 先核查双栏提取顺序、全宽标题、页眉页脚和标点，不改正确原稿来迎合检查器 |
| 缺字或字体失败 | 核实实际安装字体，调整当前模板参数后重编并重新渲染 |
| 上次中断 | 比较源哈希、已写正文和检查点，从最后真实完成边界继续 |
| 服务或执行工具拒绝 | 记录原始错误、时间和失败步骤，不猜测版权、人物或插件原因；使用正常恢复或反馈渠道，不拆分、换工具执行同一被拒绝动作来绕过拒绝 |

只有实际运行的任务才可报告“仍在处理”。不得把排版成功表述成全部人工回听完成；若只剩内容疑点，按用户接受的方括号规则交付并说明其数量或位置。
