# 原文集锦 Skill（外部文字片段 → 干净的 txt）

把一堆外部来源的文字片段（图片为主，也可以是配文/复制文字）变成一份**原汁原味、读起来顺**的 txt 集锦。

典型输入：抖音收藏下载下来的文件夹，每个图文帖子一个子文件夹（`01.jpg 02.jpg … 正文.txt`），外加少量 `.mp4`（视频）和用户手动截的图。

## 用户的硬性要求（全部来自真实反馈，不要打折）

1. **只要原文**：去掉 `#话题标签`、水印、抖音号/小红书号/@账号、作者署名、链接、点赞关注提示、截图状态栏、发帖人自己的落款签名和日期。原文自带的出处（——鲁迅、《菜根谭》）是原文一部分，保留。
2. **引用的句子一个字都不许删**：引号里的话、名言、古文原句，必须完整保留。同一句在一条里出现两遍时可以去掉重复的那一份。
3. **不改原意**：不改写、不意译、不"修正"作者的措辞和错别字。允许：加标点、改换行、修明显的 OCR 错字（多打的字、乱码）。
4. **删减上限 10%**：每条最多删 10% 的字，只能删重复句、OCR 乱码、「译文：」「释义：」这类纯标签。
5. **段落要紧凑完整**——这是用户反复纠正过的点，按下面的例子做，不要留无用换行：

   输入（OCR 原样）：
   ```
   思多乱其志，实干出真知。
   Overthinking clouds one's ambition; true knowledge dge comes from doing.
   出自《增广贤文》

   译文：
   思考过多会扰乱人的志向，只有通过实际行动才能获得得真正的知识。

   思多乱其志
   实幹出真知
   ```
   输出（用户给的标准答案）：
   ```
   思多乱其志，实干出真知。（出自《增广贤文》）Overthinking clouds one's ambition; true knowledge comes from doing. 思考过多会扰乱人的志向，只有通过实际行动才能获得真正的知识。
   ```
   - 300 字以内的条目 → **一整段，内部零换行**。
   - 出处放全角括号，紧跟在引用句后：`（出自《增广贤文》）`、`（鲁迅）`。
   - 英文译文内联跟在中文后面，不单独成段。
   - 「译文：」「释义：」「答：」这类标签能去就去；问答写成「问句？答句。」一段。
   - 长文章分几个完整段落（每段多句），不留单独一行的短句/小标题；编号条目把标题和内容合成一段；短清单合成一段用分号隔开：`1. 不炫耀；2. 把身体搞好；…`。
   - 只做"去换行"不加标点是不达标的（用户明确否定过）。
6. **视频不用识别**：用户会自己处理视频，把识别结果截图放进文件夹——那张截图里通常是**多条**独立的话，要拆开分别归类，不要当成一条。
7. **分类**：按内容主题分，不按出处分。开头放目录（带篇数），每类下按原顺序排。

## 输出格式

- 文件：`<目标文件夹的上一级>\<文件夹名>集锦.txt`（例：`D:\douyin\厉害文字集锦.txt`）。
- 编码 **UTF-8 with BOM + CRLF**（Windows 记事本友好）。
- 条目之间用 `————————————`（12 个 U+2014）隔开，前后各空一行；分类标题上下用 24 个 `=`。

```
厉害文字 · 原文集锦
（共 197 篇，按主题分类）

目录
一、行动 · 自律 · 成长（34 篇）
...

========================
一、行动 · 自律 · 成长
========================

第一条……

————————————

第二条……
```

## 流程

脚本都在 `scripts/`，用 `python -X utf8` 运行（中文路径/内容必须）。工作文件一律放 scratchpad，**不要往用户的素材文件夹里写东西**。

### 1. 摸底
统计子文件夹数、图片数、视频数、`正文.txt` 数，看 2–3 个样例（图片 + 正文.txt），确认结构。根目录散落的图片（用户的截图）单独记下，自己读图处理。

### 2. 分批 + 并行识别
```bash
python -X utf8 scripts/make_batches.py "<素材文件夹>" "<work>" --per 42
```
生成 `<work>/batchN.txt`（每块 `### NNN | 文件夹名` + 图片绝对路径）。每批派一个 subagent 用 Read 看图识别（约 40 张图/批，6 批 ≈ 2–3 分钟）。给 subagent 的要点：
- 逐字转录主体原文，保持原用字（繁体就是繁体），视觉折行先照原样；
- 按上面「只要原文」规则排除杂质；
- 多张图是同一篇的接续就按顺序拼；
- 读 `正文.txt`：配文里有图里没有的实质原文（不只是标题）才追加；配文和图片内容无关的长文不要；
- 图片纯照片无字 → 用配文里那句话；完全没字写 `[无文字]`；
- 路径含特殊字符（藏文、emoji）Read 失败时，先复制到 scratchpad 再读；
- 输出到 `<work>/outN.txt`，格式同输入的块头，**边做边追加写**。

用户手动截图那张：自己读，写成 `<work>/out0_extra.txt`，块头 `### 000 | 手动截图`，每条话之间空一行。

### 3. 汇总
```bash
python -X utf8 scripts/entries.py assemble "<work>" "<集锦.txt>"
```
解析所有 `out*.txt`，去掉 `[无文字]` 和完全重复的条目，写出未分类的集锦。完成后抽查 2 张原图和识别结果逐字对照。

### 4. 分类
自己读一遍条目开头（`entries.py list` 打印每条前 110 字），设计 8–11 个主题类，写一个映射 JSON：
```json
{"一、行动 · 自律 · 成长": [4,5,6], "二、心态 · 逆境 · 情绪": [1,2,7], "...": []}
```
手动截图里的多条话要先拆开（每条单独编号）再分类。然后：
```bash
python -X utf8 scripts/entries.py categorize "<集锦.txt>" cats_map.json
```
脚本会校验每条恰好分到一类、所有原文都还在。

### 5. 段落整理（最容易返工的一步）
```bash
python -X utf8 scripts/entries.py split "<集锦.txt>" "<work>" --chars 5500
```
生成 `ed_inK.txt`（`@@@ NNN` + 正文）和 `cats.json`。每批派一个 subagent，把「用户的硬性要求」第 2–5 条连同那个例子原样贴进 prompt，输出 `ed_outK.txt`，并要求它跑校验直到 `violations 0`：
```bash
python -X utf8 scripts/edcheck.py ed_inK.txt ed_outK.txt
```
校验内容：删减 >10%、新增 >3 个非标点字、引号内的句子丢字。（把重复句和标签合并进括号时偶尔会被标出插入了「出自」等 2–3 个字，人工看一眼确认即可。）

全部通过后：
```bash
python -X utf8 scripts/entries.py join "<work>" "<集锦.txt>"
```
再检查：300 字以内的条目里没有空行；抽 3–4 条给用户看效果。

### 6. 交付
- 动文件前先备份上一版到 scratchpad（每次大改都备份），告诉用户备份路径。
- 提醒用户：如果编辑器里还开着旧版本，先关掉重开，**别在旧窗口保存**——否则会覆盖新版（真实发生过）。
- 每次重写前先重新读一遍文件：用户可能在两轮之间手动改过（比如删掉了「哈哈哈」），要保留用户的改动。

## 踩过的坑
- 中文 regex 解析块头时 header 要用 `[^\n]*`，别用 `.*` + DOTALL，否则一口吞掉整个文件。
- Windows 下 heredoc 里的反斜杠/中文容易被搞乱，脚本写成文件再跑。
- 只按"非空白字符完全不变"约束 subagent 时，它们只会挪换行、不加标点——用户不满意。要明确允许加标点并给出例子。
